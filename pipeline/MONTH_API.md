# Month API contract (`agrinet-month-1`)

**Frontend integration:** Generate once with `uv run python -m pipeline.month_opportunities --out web/public/month-api`; this refuses an existing output directory and never fetches from data.gov.in. Static fetch paths are `month-api/catalog.json` and `month-api/{product_slug}/{YYYY-MM}.json`; use the deployment base URL. Catalog `products` includes **every distinct slug** in the retained 2021–2026 archive, including unsupported products and months without a route. Each product has `name`, `source_names`, `months` (only months actually observed), `raw_rows` (all months), `supported_product`.

Month payload: `{schema,product,product_name,month,source,latest_observation,status,coverage,opportunities,chains,caveats}`. `status` is `modeled_scenarios_only`, `no_supported_opportunity`, `unsupported_product`, `unsupported_cost_period`, or `no_source_observations` (the last applies to a direct Python request, not generated paths). Empty `opportunities` means no supported positive **modeled** day among analyzed routes, not proof that no profitable deal existed. Coverage contains `scope: "cached_named_place_roads_only"`, `clean_market_variety_days_in_month`, `routed_pairs_considered`, `matched_pairs`, `matched_days`.

Each opportunity has `origin`/`destination` stable market keys, `origin_market`/`destination_market` (name/state/district/lat/lon/precision/key), `commodity`,`variety`,`grade`, `route` (key/km/transit_days/provider/profile/truck_suitable=false; geometry stays in the separately retained route cache), ISO `buy`/`sell`, INR/quintal `buy_price`,`sell_price`,`gross`,`net_baseline`,`net_adverse`, `known_destination_date` (strictly before buy), `expected_net_on_buy_day`, `cost_scenarios`, `assumptions`, and verdict `positive_retrospective_modeled_surplus_not_verified_profit`. Select only same-variety/grade pairs with >=12 matched reports and >=4 distinct prices at each end, positive pre-purchase informed decision and positive realized baseline/adverse modeled surplus, plus gap sanity limits. The later sale is **not** information available on purchase day.

`chains[]` is per `(commodity,variety,grade)` and contains `legs[]`, `modeled_net_per_initial_qtl`, and `selection`. Dynamic programming maximizes hindsight sum for **one initial quintal** without compounding, ensuring each subsequent buy is at the previous sale market **after sale + 7-day settlement**. Capital may not fund overlapping legs; no relocation or parallel allocation. No fixed initial working-capital budget or cash-feasibility check is modeled, so chain totals are additive scenario units, **not** a feasible financed portfolio. This is a retrospective thought experiment with selection bias, not an implementable strategy or verified profit. Do not add its margin to a trade prediction or call the search exhaustive: geography is bounded by existing cached OSRM routes, not all India pairs; there are no actual freight quotes or executable bids.

The original static `stories/catalog.json` and story files are a separate, bounded survivor feed; do **not** use them as month API coverage.
